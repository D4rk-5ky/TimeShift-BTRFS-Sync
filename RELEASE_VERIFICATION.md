# Release verification — TimeShift-BTRFS-Sync 0.2.1

Created on 2026-10-13. Increment the previous source release by exactly 0.0.1: 0.2.0 → 0.2.1. Complete prior version history remains in uppercase VERSIONING.md.

## Changes

- Recognize Timeshift's specific exit-1 startup lock denial with PID and wait 60 seconds between retries. Report normal waiting and availability; no automatic timeout, process signaling or Timeshift lock manipulation. Ctrl+C retains existing interruption handling (exit 130). A scheduled run or open GUI can hold the same lock, so the app does not assert that the reported PID is an hourly job. Primary source: [startup lock check](https://github.com/linuxmint/timeshift/blob/master/src/Core/Main.vala) and [PID lock implementation](https://github.com/linuxmint/timeshift/blob/master/src/Utility/AppLock.vala).
- Retry the complete local/SSH source inventory, discarding every busy attempt. Rebuild Timeshift names/tags/comments, ordinary-readable info.json, snapshot_root/cache_root native UUID/readonly views and effective source identity. Local Btrfs/JSON discovery starts only after Timeshift listing succeeds. The existing sync planner and transfer recovery receive refreshed data for new dates, removed dates and O/H/D/W/M/B changes. Waiting does not consume source-change recovery retries.
- Use the same startup-denial helper for standalone source list, test-source and on-demand create. Successful sync creation already refreshes full inventory and keeps that behavior. Do not replay combined destructive delete-plus-list commands; unrelated command/permission/SSH and partial-creation failures still propagate. Diagnostic list-snapshots keeps its existing native fallback. The recognized message is the supplied English Timeshift startup denial with PID; unexpected/translated errors are not silently treated as a lock.
- Update current-use README, INSTALL, uppercase VERSIONING/COMMENTED_CODE_MAP, current config/CLI audit, sync --help, all eight example comments and source/build version metadata. Preserve all original necessary and prior release files, requirements and both supplied disclaimers.
- Runtime changes compared with 0.2.0 are limited to the Timeshift wait/command helper, inventory retry wrapper/local Timeshift status capture and remote busy classification, CLI test-source invocation/help, and source version metadata. Source/SSH transport, Btrfs facade, native reader protocols, state schema, sync/send/receive, retention/reconciliation/deletion and restore modules are byte/mode-unchanged. No new config key, Python dependency or sudo command is introduced.

## Limits

Live Timeshift scheduling/GUI-lock concurrency, Btrfs snapshot creation/send/receive/deletion, real SSH/account sudo permissions, transfer/restore interruption and notifications were not exercised. Reader identities, source changes, successful-sync cleanup and wait intervals are simulated; shell/JSON/log/CLI fixture I/O is real. Python 3.11, complete dependency installation and MQTT/PyInstaller builds remain untested. Preserved dist/ts-btrfs remains 0.1.84; use/install the current Python source or rebuild it.

The app waits indefinitely for the recognized lock denial; an open GUI or persistent Timeshift run can keep it waiting until Ctrl+C or source-side resolution. Readiness is checked by retrying the allowed Timeshift command, with up to 60 seconds plus command time before the next attempt. A successful list does not lock out a subsequent external Timeshift run; existing native UUID/path checks and source-change recovery remain necessary. No timeout or extra permission is hidden in configuration.

Ordinary Timeshift source retention and all earlier cleanup ownership/UUID/readonly/consent/success gates remain unchanged. The original upload and previous release archives remain unchanged. Extract this ZIP into a fresh directory to avoid carrying obsolete files from another copy forward.
