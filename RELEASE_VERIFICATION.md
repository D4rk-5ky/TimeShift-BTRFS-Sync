# Release verification — TimeShift-BTRFS-Sync 0.2.2

Created on 2026-10-19. Increment 0.2.1 by exactly 0.0.1 to 0.2.2. Preserve full uppercase VERSIONING history and all 100 prior project files.

## Changes

- Add optional, independent per-config live MQTT status with canonical config-path/hostname ID, display name fallback, unique run ID, UTC timestamps, phase, heartbeat, runtime, snapshot-date counters and known transferred bytes. Strict [mqtt_monitor] options are included in all eight profiles, disabled by default. Reuse [mqtt] broker/auth/QoS/timeout separately from completion enablement/topics/retain/filters.
- Derive initial date totals from the existing retained metadata queue, without any stream sizing preflight. A complete snapshot date requires all configured payloads and info.json. Refresh the complete local/SSH source inventory at successful real date boundaries and rebuild remaining work through the existing retention/planning functions. Keep completed history when flags change or source dates expire; new/pending eligibility can grow or shrink totals. Respect sync floor, prior complete dates and existing soft payload --limit semantics. Label unavailable source dates as skipped, keep failures partial, and invalidate only recovered failed-date versions. Console summary adds date progress without changing payload-counter meanings.
- Activate live status only after the existing exclusive real-sync flock. Duplicate launches publish events only; dry-runs and non-sync commands do not publish live backup status. Heartbeats run independently of long sends/Timeshift waits; updates are coalesced. Broker/import/thread failures do not fail healthy replication. Bound final drain to one second and cancel further publishing after the deadline, including a slow connection returning later. Already-sent packets can still arrive late; no durable MQTT outbox is added.
- Publish non-retained status/events and retained last_result/discovery. Group twelve HA sensors under one backup device; live sensors expire after 180 seconds by default while last result remains. Include built-in-card dashboard and disabled optional heartbeat-loss/runtime automation YAML. Missing heartbeat means unknown availability, not confirmed backup failure. No Pushover service integration or new start alerts are enabled.
- Reuse the broker publisher for legacy and live messages, with the Paho network loop active during QoS acknowledgement, credential handling, unique live client suffixes, connect/loop cleanup and optional cancellation. Preserve existing notification filters and backup exit behavior.
- After boundary refresh, absent/changed UUID/lineage or non-readonly parents lose in-run trust and must pass existing validation again. Preserve native UUID/receive safety, source retention permissions, cleanup consent/success gates and deletion engine. State schema, inventory reader protocol, source/SSH transport, Btrfs facade, restore, retention/reconciliation and tree deletion modules are unchanged from 0.2.1.
- Update current README/INSTALL, uppercase VERSIONING/COMMENTED_CODE_MAP, config audit, all eight examples, sync help, version metadata and config/public-surface tests. New files are monitor.py, test_live_monitor.py and two Home Assistant YAML examples. Preserve requirements, original executable, original LICENSE and both supplied disclaimers.

## Limits

No live MQTT broker, installed Home Assistant, Paho socket delivery, Btrfs snapshot/send/receive/deletion, Timeshift scheduler concurrency, real SSH/sudo account, restored boot or production notifications were exercised. Streams/native IDs/receiver mutation and broker delivery are simulated; ordinary files/processes/flock/state/log I/O are real. YAML/templates are checked offline, not installed in HA. Python 3.11, complete requirements installation and MQTT/PyInstaller builds remain untested. The preserved dist/ts-btrfs reports 0.1.84; use/install the current Python source or rebuild.

Monitoring is opt-in, not a replication dependency or durable message queue. Outages/abrupt exits can lose final or event packets; packets already on the wire may arrive late despite cancellation. Use run IDs/timestamps for independent consumers. HA live state also expires normally while idle; consult retained last_result for finished runs. Broker discovery ACLs and actual HA entity IDs must be adapted. Moving config/changing hostname creates a different identity. Refresh is metadata-only but adds source inventory I/O at real date boundaries; external changes after the final view belong to a future invocation. Known byte counts exclude in-flight/unknown/invalidated payloads.

Ordinary Timeshift source retention, deletion ownership/UUID/readonly/consent/success safeguards and restore permissions remain intact. Original upload and all earlier release archives remain unchanged. Extract into a fresh directory to avoid carrying old files from another copy forward.
