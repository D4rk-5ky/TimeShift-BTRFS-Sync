# Release verification — TimeShift-BTRFS-Sync 0.1.93

Created on 2026-10-12, incrementing 0.1.92 by 0.0.1.

## Changes

- Added `list-snapshots --config FILE`, which prints Timeshift-style source send-cache and destination backup tables plus separate device/mount/filesystem and df total/used/available space. `--include-timeshift` adds the original Timeshift table. `--workflow auto|backup|restore` covers all supported local/SSH backup and restore combinations; auto chooses non-local restore modes, otherwise backup.
- Reused the existing source/endpoint transports, restore repository endpoint mapping, topology descriptions, physical directory/info.json scanner and Btrfs command facade. The scanner receives an empty privilege prefix and Btrfs commands use an explicitly empty sudo setting. Btrfs property get -ts PATH ro verifies payload roots and readonly status without privileged B-tree searches. Probes use bounded batches, no temporary files and no connection per payload; batches remain below shell argument-size limits for large inventories.
- Source cache metadata comes from current same-date original Timeshift info.json; missing originals keep physical cache dates visible with unknown tags/descriptions. Destination reads its own info.json. Native named retention tags and compact letters are parsed without inventing O/B tags from words such as hourly. Terminal controls are sanitized. Dates with incomplete/denied/unverified payloads remain visible, and symlink entries are not followed. Counts are dates, not @/@home payload totals. Complete is presence/flag observation only, not restore eligibility or UUID lineage proof.
- Reports endpoint failures independently and exits 1 after printing both sides. Legitimately empty inventories and disabled cache are distinguished from unavailable reads; unknown metadata alone does not fail. A disabled cache reports the source snapshot-root filesystem. Wrong filesystem types and unavailable df readings are reported as failures. Existing mounts and account read/search permissions are required.
- Updated README.md, INSTALL.md, canonical VERSIONING.md and COMMENTED_CODE_MAP.md, current config audit, all eight template headers, release metadata and public-surface expectations. Added listing.py and its regression tests. All 95 prior release files are retained; 97 files are packaged. No lowercase/package-local duplicate docs or ignore file was reintroduced.
- Existing sync, incremental/full transfer, retention, cache maintenance, restore, locking, state, notification, ownership and deletion safety modules are byte-identical to 0.1.92. Ordinary Timeshift source retention remains managed by Timeshift. The listing handler bypasses app state/locks/logging/notifications and does not mount, create, transfer, prune or restore.

## Limits

Live Timeshift repository inventory and SSH endpoint integration were not performed; host mappings and failures were exercised with simulations and local physical fixtures. No live backup, restore, deletion or notification deployment was tested. Python 3.11 was not exercised. Full MQTT/PyInstaller dependency installation and executable rebuilding were not repeated. The preserved original dist/ts-btrfs remains 0.1.84; run the current source/installed package or rebuild it to get list-snapshots.

This is an observational listing without locks. Concurrent changes may affect rows. Tags/descriptions need readable Timeshift info.json files and are unknown when the original source date expired. The Btrfs readonly property does not establish UUID lineage or restore safety. df reports shared filesystem availability rather than exclusive snapshot usage or a guarantee of enough Btrfs receive space. The command adds no sudo prefix; it retains the privileges of the local/SSH account chosen by the user.

The original and previous release archives are unchanged. Extract the release into a fresh directory; copying over an old checkout can retain already removed nested files. README.md and INSTALL.md explain all command flags and how to install/build the current source.
