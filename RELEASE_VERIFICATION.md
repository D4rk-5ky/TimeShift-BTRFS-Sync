Created on 2026-10-13. Increment 0.1.99 by 0.0.1 with the required patch-99 rollover: 0.1.99 → 0.2.0. No patch-100 version is created.

## Changes

- Remove the lower date bound from destination-only redundant snapshot cleanup. Consider all untracked/unprotected calendar-valid Timeshift date names no newer than the newest complete live UUID-confirmed state pair, including leftovers older than the oldest retained pair. Every newer date remains outside this extra cleanup so it can be used by a future transfer.
- Preserve dedicated native source-cache/destination-root ownership, canonical complete state/cache/Received UUID anchors, exact UUID/ID/readonly/lineage and containment checks, source identity overlap rejection, known-source/cache-stream protection, fresh cache absence, protected/tracked/incomplete-parent guards, requested cleanup, explicit --yes-delete and successful-current-sync gating. Use the existing deletion engine without any change. Missing proof or partial inventories preserve snapshots. Ordinary Timeshift original retention stays managed by Timeshift.
- Source redundant-cache cleanup already has no lower date limit and retains its existing upper-only policy. Both independent source/destination delete_redundant_snapshots settings still default true; no new option is added. Real extra deletion occurs only after successful sync and paired retention. Standalone dry prune previews extras; standalone real prune skips them; listing and restore remain read-only with respect to this cleanup.
- Listing retains its physical shared-range diagnostics and adds destination-only counts at/before and after the latest shared pair. Older-than-first dates are labeled for prune safety checking, and newer-than-latest observations are labeled for comparison with the state cutoff. Listing does not read state; actual deletion uses the freshly UUID-confirmed state upper limit.
- Update current-use README, INSTALL, uppercase VERSIONING/COMMENTED_CODE_MAP, current config/CLI audit, all eight config comments and help/version metadata. Preserve every prior file, complete prior version history, requirements/extras, original executable and both supplied disclaimers.
- Runtime changes compared with 0.1.99 are limited to destination candidate selection/output/docstring in reconciliation.py, listing text/counters, source version metadata and config/CLI explanatory text. Retention orchestration, ownership and UUID proof, tree deletion, state schema, inventory, source/SSH transport, cache creation, send/receive and restore modules are unchanged. No additional sudo command or ordinary recursive deletion is introduced.

## Limits

Live Btrfs snapshot creation/send/receive/deletion, Timeshift mounting/listing, user remote account/passwordless sudo, real transfer/restore interruption, network churn and notifications were not exercised. Native identities, successful sync and mutations are fixtures; ordinary local fixture I/O is real. Python 3.11, complete dependency installation and MQTT/PyInstaller builds remain untested. Preserved dist/ts-btrfs remains 0.1.84; run/install the current Python source or rebuild it.

The newest confirmed cutoff excludes newer dates; other tracked, excluded, writable or uncertain snapshots can remain. Counts therefore need not be equal. Extra cleanup removes contents inside qualifying authorized dedicated Btrfs date trees under the existing user-authorized policy. Btrfs ID deletion support is required. App locking cannot stop unrelated external filesystem changes, and final ID absence confirms namespace removal rather than complete asynchronous space reclamation. These are unchanged limits.

Uploaded original and earlier release archives remain unchanged. Extract into a fresh directory so obsolete files from other copies are not carried forward.
