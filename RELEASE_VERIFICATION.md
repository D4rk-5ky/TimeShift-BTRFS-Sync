# Release verification — TimeShift-BTRFS-Sync 0.1.98

Created on 2026-10-12, incrementing 0.1.97 by 0.0.1.

## Changes

- With source.delete_redundant_snapshots=true and the existing cleanup master switch/consent, real extra cache deletion now runs only after successful real sync in the current invocation and paired retention. Failed sync never calls prune. A completed no-op sync can qualify when fresh full existing pairs prove ownership. Standalone prune dry-run previews extras; standalone real prune retains existing paired retention but reports that redundant extras require successful sync.
- Refresh cache/receiver native views after paired cleanup. Prove a native dedicated cache-root UUID/ID and complete numeric containment; reject native overlap with Timeshift source identities. Cache-backed complete state entries must resolve to canonical same-date cache and receiver paths, match recorded send UUIDs to fresh readonly cache UUIDs and received UUIDs, and include at least one complete cache anchor. Incomplete transfer state or incomplete/changed/unknown ownership preserves extras.
- Recognize untracked Timeshift-style native date subvolumes no newer than the latest proven state pair: readonly native snapshots or native containers of readonly snapshots. Include older-than-first-retained dates and partial/legacy readonly cache layouts. Preserve tracked/protected/newer dates, referenced parents, existing/uncertain receivers and writable/foreign/changed subtrees. Extra cleanup never deletes a receiver or Timeshift original.
- Under the user's explicit dedicated-cache ownership policy, ordinary cache traversal, cache JSON and ordinary file-entry checks are no longer deletion prerequisites. Contents inside qualifying Btrfs date trees are removed with their subvolumes. No sudo shell/file reader, permission/ownership change or recursive ordinary deletion is added.
- Extend the existing shared tree engine with NativeCacheDeletionProof, used only for this extra cleanup. Recheck exact subtree UUIDs, IDs, readonly/native lineage, root identity and containment. Refuse identities moved outside the cache/date or newly added native subvolumes. Delete deepest-first using configured Btrfs subvolume delete --commit-after --subvolid on the anchored filesystem. Confirm every command and final ID absence through the unchanged surviving root. Unsupported flags, partial failures or incomplete views never claim success. All other tree-deletion callers keep their original entry safeguards.
- Retain numeric IDs in the existing inventory parser so list/show identities agree. Add skipped-gate reporting to source cleanup summaries. Update current README/INSTALL, uppercase VERSIONING/COMMENTED_CODE_MAP, config/CLI audit, all eight profile comments/headers, CLI help and package/helper/source version metadata. Preserve both disclaimers, requirements/extras, original necessary files and prior version history.
- Runtime changes are limited to reconciliation.py, tree_ops.py, inventory.py, retention.py and cli.py, plus listing diagnostic wording, source config comments and version metadata. State schema, source/SSH transport, Btrfs facade, cache creation, send/receive pipeline, native restore, ordinary Timeshift source deletion policy and dependency declarations remain unchanged.

## Limits

Live Btrfs snapshot creation/send/receive/deletion, Timeshift inventory/mounting, the user's remote account/passwordless sudo policy, real transfers/restores, network churn and notifications were not tested. Native identities, successful sync stage and storage mutation are simulated; ordinary local JSON/directory/df/state/lock/log operations are real. Python 3.11, full dependency install and MQTT/PyInstaller build were not exercised. Preserved dist/ts-btrfs remains 0.1.84; run/install the current source or rebuild.

This policy intentionally permits removal of contents inside proven dedicated-cache date trees without ordinary visibility. Use a dedicated cache_root per job. It requires source Btrfs --subvolid and --commit-after support; unsupported commands keep explicit retry errors. Identity checks precede deletion but cannot lock out unrelated external filesystem mutations; app commands use the existing job lock. Final ID absence describes namespace removal, not complete asynchronous reclamation of data blocks. See the official [Btrfs subvolume documentation](https://btrfs.readthedocs.io/en/latest/btrfs-subvolume.html) for ID deletion, transaction commit and background cleaning.

No ordinary Timeshift snapshot or destination is deleted by the extra option. Protected/tracked/newer/ambiguous cache dates can remain after successful cleanup. Listing stays read-only, and standalone prune never executes real extra cleanup. Earlier archives/upload are unchanged. Extract into a fresh directory to avoid carrying obsolete files forward.
